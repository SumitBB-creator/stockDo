1. ARCHITECTURAL OVERVIEW & THRESHOLD MONITORING SYSTEM
--------------------------------------------------------------------------------
The Material Shortage Notice module is the "Operational Early-Warning System" of StockDo. 
In commercial scaffolding and building asset leasing, maintaining high stock availability 
in the central yard is critical. If assets are over-leased, inbound orders cannot be fulfilled, 
leading to lost revenue and customer dissatisfaction.

To prevent yard shortages, the system implements a real-time threshold monitoring system 
that compares dynamic available stock against safety stock limits defined in the material master:

- Total Stock ($\text{totalQty}$):
  The master physical count of an asset registered in the yard ledger.
- Issued Stock ($\text{issuedQty}$):
  The total amount of an asset currently deployed across all customer sites, computed by 
  replaying all chronological `ISSUE` and `RETURN` challans:
  $$\text{issuedQty} = \sum (\text{ISSUE}) - \sum (\text{RETURN})$$
- Available Stock ($\text{availableQty}$):
  The net quantity currently sitting in the central yard, ready for dispatch:
  $$\text{availableQty} = \text{totalQty} - \text{issuedQty}$$
- Lower Limit ($\text{lowerLimit}$):
  The safety threshold or "Re-order Point" defined in the Material Master records. 

--- NOTICE TRIGGER BOUNDARY ---
An asset is flagged and listed on the Shortage Notice board if and only if the current available 
stock drops to or below the safety threshold:
$$\text{availableQty} \le \text{lowerLimit}$$

--- CRITICAL STATUS CLASSIFICATION ---
To help procurement managers prioritize inventory restocking, flagged items are sub-divided 
into two alarm categories:
1. LOW STOCK (Warning):
   The yard inventory has crossed into the safety buffer but retains items:
   $$0 < \text{availableQty} \le \text{lowerLimit}$$
2. CRITICAL OUT (Danger):
   The yard inventory is completely exhausted. Every single unit of this asset is currently 
   deployed or lost, making dispatch of new orders impossible:
   $$\text{availableQty} = 0$$

2. DATABASE RELATIONAL SCHEMA
--------------------------------------------------------------------------------
Shortage metrics are derived dynamically from the `Material`, `Challan`, and `ChallanItem` 
models in the PostgreSQL database.

* Schema File Location: [schema.prisma](file:///c:/Users/lenovo/Desktop/stockDo/backend/prisma/schema.prisma)

1. Model: Material (`materials` table)
   - id: String (UUID, PK)
   - materialId: String (Unique. e.g. M0001)
   - name: String (Material descriptive title)
   - unit: String? (UOM e.g. 'Nos', 'Mtr')
   - totalQty: Int (Master total physical quantity in inventory)
   - lowerLimit: Int (Safety threshold trigger)
   - hireRate / damageRecoveryRate / shortRecoveryRate: Float
   - status: String (Active / Inactive)

2. Model: Challan (`challans` table)
   - id: String (UUID, PK)
   - type: ChallanType (Enum: 'ISSUE' or 'RETURN')
   - items: ChallanItem[] (Nested lines array)

3. Model: ChallanItem (`challan_items` table)
   - id: String (UUID, PK)
   - challanId: String (UUID, FK to challans)
   - materialId: String (UUID, FK to materials)
   - quantity: Int (Quantity issued or returned)

3. FRONTEND CONTROLLER & DYNAMIC ALERT BOARD
--------------------------------------------------------------------------------
* File Location: [page.tsx](file:///c:/Users/lenovo/Desktop/stockDo/frontend/src/app/dashboard/stock/shortage/page.tsx)

The Shortage Notice Board is an interactive, dark-themed Next.js client component ('use client') 
that renders flagged materials. It displays warning panels, filter bars, a loading skeleton 
animating during calculations, and visual badges displaying alerts.

--- FRONTEND ALERT ENGINE FEATURES ---
- Real-time search query matching: filters matching materials instantly by `materialName` or `unit`.
- Visual badge indicator mapping:
  - Blinking red badge (`animate-pulse`) labeled **CRITICAL OUT** if available quantity reaches $0$.
  - Amber badge labeled **LOW STOCK** if available quantity resides within the safety buffer range.
- Empty states: renders a full-page SVG graphic (`Package` icon) if all inventory resides safely 
  above their safety thresholds.
- Dynamic warning footer callout card detailing safety stock logic to site managers.

--- B. TRANSACTION REPLAY SERVICE METHOD ---
* File Location: [challans.service.ts](file:///c:/Users/lenovo/Desktop/stockDo/backend/src/challans/challans.service.ts)

Method execution steps:
1. Fetch Materials:
   Gathers all materials registered in the `Material` master table.
2. Fetch Chronological Challan History:
   Loads all `Challan` records along with their nested `ChallanItem` arrays.
3. Compute Active Issued Quantities (`issuedMap` tracker):
   Iterates through every challan line item:
   - If the challan is an `ISSUE` (outward stock movement to site):
     $$\text{issuedQty} = \text{issuedQty} + \text{item.quantity}$$
   - If the challan is a `RETURN` (inward stock movement from site):
     $$\text{issuedQty} = \text{issuedQty} - \text{item.quantity}$$
     *Safety Guard:* To protect against raw human input discrepancies, the subtraction is 
     wrapped inside a `Math.max(0)` boundary statement to prevent negative issued quantities:
     $$\text{issuedQty} = \max(0, \text{issuedQty} - \text{item.quantity})$$
4. Map Net Yard Available Quantities:
   Loops through the materials array, matches the compiled issued quantity, and subtracts 
   it from the master total physical stock:
   $$\text{availableQty} = \text{totalQty} - \text{issuedQty}$$
   It flattens and returns a standardized data transfer payload containing:
   `materialId`, `materialName`, `unit`, `totalQty`, `lowerLimit`, `issuedQty`, `availableQty`.

--- FULL CODE LISTING ---
```typescript
async getCompanyStock() {
    // 1. Fetch all materials
    const materials = await this.prisma.material.findMany();

    // 2. Fetch all challans and their items
    const allChallans = await this.prisma.challan.findMany({
        include: { items: true },
    });

    // 3. Map to keep track of issued quantities
    const issuedMap = new Map<string, number>();

    for (const challan of allChallans) {
        for (const item of challan.items) {
            const currentIssued = issuedMap.get(item.materialId) || 0;

            if (challan.type === 'ISSUE') {
                issuedMap.set(item.materialId, currentIssued + item.quantity);
            } else if (challan.type === 'RETURN') {
                // Prevent negative issued stock, assuming data might have discrepancies
                issuedMap.set(item.materialId, Math.max(0, currentIssued - item.quantity));
            }
        }
    }

    // 4. Combine material total stock with issued stock to calculate available stock
    return materials.map(material => {
        const issuedQty = issuedMap.get(material.id) || 0;
        const availableQty = material.totalQty - issuedQty;

        return {
            materialId: material.id,
            materialName: material.name,
            unit: material.unit,
            totalQty: material.totalQty,
            lowerLimit: material.lowerLimit,
            issuedQty,
            availableQty,
        };
    });
}
```

6. OPERATIONAL PROCUREMENT WORKFLOW
--------------------------------------------------------------------------------
When materials drop below safety thresholds, the operational team uses the following 
standard flow to restock:

1. Alert Assessment:
   The Yard Manager accesses the Shortage Notice board daily to assess flagged items.
2. Filter & Prioritization:
   The search bar is used to filter by material name. Managers target **CRITICAL OUT** items 
   first, followed by **LOW STOCK** warnings.
3. Export List:
   Clicking the **Export List** button triggers a CSV download containing columns: 
   Material ID, Name, Total, safety limit, and currently available yard stock, which is 
   forwarded to purchasing.
4. Material Limit Adjustments:
   If safety buffers need to be altered due to seasonal demand shifts, managers navigate to 
   the **Material Master** settings panel, locate the material, edit the `lowerLimit` integer, 
   and click save. The Shortage Notice board adjusts its alert filters immediately upon 
   the next refresh.
