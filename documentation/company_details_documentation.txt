================================================================================
STOCKDO: COMPANY DETAILS EXHAUSTIVE DOCUMENTATION
================================================================================

This document covers the Company Details module, which acts as the global settings 
and root identity provider for the entire StockDo ERP instance. 

--------------------------------------------------------------------------------
1. ARCHITECTURAL OVERVIEW (THE SINGLETON PATTERN)
--------------------------------------------------------------------------------
Unlike Customers, Suppliers, or Employees, the Company module follows a strict 
Singleton Pattern. The ERP is designed to run for a single parent organization. 
Therefore, you cannot "create multiple companies" nor "delete" the company in 
the traditional CRM sense.

Instead, the database only ever holds one active `Company` record. 
- Creating: Handled by the first `updateCompany` call (if no record exists).
- Editing: Updates the existing single record.
- Deleting: Not exposed to the frontend UI to prevent catastrophic data orphans.

The data stored here (Address, GSTIN, State Code) is dynamically injected into 
every Delivery Challan, Bill, and Purchase Order generated by the system.

--------------------------------------------------------------------------------
2. FRONTEND CONTROLLER & INTERFACE
--------------------------------------------------------------------------------
* Page Location: `frontend/src/app/dashboard/company/page.tsx`

The interface is a monolithic, highly structured form divided into logical blocks, 
powered by `react-hook-form` and `zod`.

--- UI LIFE-CYCLE ---
1. Data Fetching (Read/Detail View):
   `loadCompany()` runs on mount, fetching the singleton record via `GET /company`.
   If a record exists, `form.reset(data)` hydrates the massive form instantly. 
   If it returns empty (e.g., first boot), the form remains blank for initial setup.

2. Form Sections:
   - Basic Info: Company Name, Employer, Email, Website, Phone, Fax.
   - Address Details: Address lines, City, State, State Code, Country, PIN.
   - Tax & Banking: PAN, GSTIN, Bank Name, Account No, IFSC.
   - Advanced Financials: 
     - `fixedAssetsValue`: Used directly in the Balance Sheet report to offset 
       liabilities.
     - `gstOnTransportation` (Boolean): Dynamically unhides if a GSTIN is provided. 
       When true, the Billing engine knows to tax freight charges.
   - Branding: A file upload input for the Company Logo (`uploadLogo` API call).

3. Saving (Create/Edit):
   Clicking "Save Details" triggers the `onSubmit` handler, pushing the entire 
   payload to `POST /company/update`. The UI shows a loading spinner to prevent 
   double-submissions.

--------------------------------------------------------------------------------
3. BACKEND SERVICE & SINGLETON LOGIC
--------------------------------------------------------------------------------
* API Router: `backend/src/company/company.controller.ts`
* Service logic: `backend/src/company/company.service.ts`

--- THE `updateCompany()` PIPELINE ---
When a POST request hits the server:
1. The service calls `prisma.company.findFirst()`.
2. UPSERT LOGIC: 
   - If a record exists, it runs an `update` using the existing record's `id`.
   - If no record exists, it runs a `create`.
3. LEDGER INTEGRATION: The company is also assigned a `ledgerAccountId`. If one 
   doesn't exist, it generates a `randomUUID()`. This allows the company itself 
   to act as an entity in the Daybook and Transaction ledgers for capital injections.
