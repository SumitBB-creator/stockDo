STOCKDO: SALE REPORTS EXHAUSTIVE DOCUMENTATION (LOCAL & CENTRAL)
================================================================================

This document covers both the Local Sale and Central Sale modules under the 
Sale Report section.
- LOCAL SALE: Aggregates intra-state sales taxed using a split of CGST and SGST.
- CENTRAL SALE: Aggregates inter-state sales taxed using a unified IGST.

These reports are crucial for GST filing, as they provide an itemized list of all 
revenue generated and the specific tax components collected.

--------------------------------------------------------------------------------
1. ARCHITECTURAL OVERVIEW & SHARED COMPONENT
--------------------------------------------------------------------------------
Instead of building distinct database endpoints for "Local Sales" and "Central Sales", 
StockDo leverages a single generic React component: `<SaleReport />`.

This component uses the existing `fetchFilteredBills` API from the Billing engine. 
It pulls all bills for the requested date range and performs a client-side filter 
based on a passed `type` prop:
- If `type === 'LOCAL'`, it filters `bill.gstType === 'CGST_SGST'`
- If `type === 'CENTRAL'`, it filters `bill.gstType === 'IGST'`

This DRY (Don't Repeat Yourself) architecture ensures that if a bill is modified 
or cancelled in the main Billing module, both reports instantly reflect the change 
without needing a separate data synchronization job.

--- COMPONENT INJECTION ---
The specific pages are incredibly lightweight, simply passing props to the core component:

```tsx
// frontend/src/app/dashboard/sale-report/local/page.tsx
import { SaleReport } from '@/components/accounting/sale-report';
export default function LocalSalePage() {
    return <SaleReport type="LOCAL" title="Local Sale Report (CGST/SGST)" />;
}
```

```tsx
// frontend/src/app/dashboard/sale-report/central/page.tsx
import { SaleReport } from '@/components/accounting/sale-report';
export default function CentralSalePage() {
    return <SaleReport type="CENTRAL" title="Central Sale Report (IGST)" />;
}
```

--- CORE UI LIFE-CYCLE (`sale-report.tsx`) ---
1. Date Bounding:
   Defaults to the current calendar month using date-fns (`startOfMonth`, `endOfMonth`).
2. Data Fetching & Filtering:
   Calls `fetchFilteredBills` to retrieve the bills, then filters by the `type` prop.
3. In-Memory Search:
   Users can rapidly search for a specific `billNumber` or `customer.name` without 
   making additional network requests.
4. Mathematical Aggregation:
   A `reduce` function iterates over the filtered (and searched) bills to calculate 
   dynamic totals for the bottom of the table:
   - Total Taxable Amount
   - Total CGST & SGST (if Local) or Total IGST (if Central)
   - Grand Total
5. Presentation:
   The table displays comprehensive tax metadata for each bill, including:
   - Customer Name & Address
   - Customer GSTIN/UIN
   - State Name and State Code
   - Bill Date & Bill Number
   - Taxable Amount

--------------------------------------------------------------------------------
3. PRINT & EXPORT LOGIC
--------------------------------------------------------------------------------
Clicking "Print / Export" constructs a query string containing the `type`, `fromDate`, 
`toDate`, and `searchTerm`. It opens a new tab pointing to `/dashboard/sale-report/print`, 
which strips away all navigation and sidebars, rendering a clean, A4-optimized 
report ready for physical printing or PDF export.

```typescript
// Print routing logic inside sale-report.tsx
const handlePrint = () => {
    const params = new URLSearchParams({
        type, 
        fromDate: fromDate.toISOString(),
        toDate: toDate.toISOString(),
        searchTerm
    });
    window.open(`/dashboard/sale-report/print?${params.toString()}`, '_blank');
};
```
