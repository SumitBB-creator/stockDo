================================================================================
STOCKDO: MATERIALS EXHAUSTIVE DOCUMENTATION
================================================================================

This document covers the Materials module. Materials (often referred to as Items 
or Inventory) are the foundational product units in StockDo. They define what is 
rented, sold, or purchased.

--------------------------------------------------------------------------------
1. ARCHITECTURAL OVERVIEW
--------------------------------------------------------------------------------
Unlike Ledgers and CRM entities (Customers/Suppliers) which dictate the "Who", 
the Materials module dictates the "What". 

A Material record holds metadata like:
- HSN / SAC Codes (Crucial for GST classification in Billing and Purchases)
- Units of Measurement (e.g., Kg, Pcs)
- Quantitative limits (Total Qty, Damage Qty, Short Qty, Lower Limit thresholds)

When a Material is created, the system auto-generates a unique `materialId` 
(e.g., `M0001`, `M0002`). This ID is used relationally across `ChallanItem`, 
`BillItem`, and `PurchaseItem` tables to ensure referential integrity.

--------------------------------------------------------------------------------
2. FRONTEND CONTROLLER & INTERFACE
--------------------------------------------------------------------------------
* Page Location: `frontend/src/app/dashboard/materials/page.tsx`

The Materials interface is unique among the Master Data pages because it employs 
a hybrid approach to data entry to optimize for rapid inventory building.

--- UI LIFE-CYCLE & FEATURES ---
1. Dynamic Column Visibility:
   The page includes a specific "View Columns" dropdown (`lucide-react` Settings2 icon). 
   This allows users to toggle visibility for 11 different columns (Action, Name, 
   Unit, HSN, SAC, TotalQty, etc.) on the fly, saving screen real-estate.

2. The "Quick Add" Inline Row (Create):
   Unlike Customers where you MUST open a modal to add a record, the Materials 
   table features a permanent, inline input row at the absolute bottom of the table.
   - Users can type the Name, Unit, HSN, and Qty directly into the table cells.
   - Hitting the `Enter` key (`handleKeyDown`) captures the state, fires the POST 
     request to create the material, instantly refreshes the table, and focuses 
     the cursor back to the Name input so the user can rapidly type out dozens 
     of items without touching the mouse.

3. The Dialog Modal (Edit):
   Clicking the "Edit" hyperlink on a row opens a traditional `Dialog` powered 
   by `react-hook-form` and `zod` for editing existing data without cluttering 
   the inline view.

4. Deletion:
   Clicking "Delete" triggers a browser confirmation. Deleting a material drops 
   it from the system, provided it hasn't been locked by existing Challans or Bills.

--------------------------------------------------------------------------------
3. BACKEND SERVICE & ID GENERATION LOGIC
--------------------------------------------------------------------------------
* API Router: `backend/src/materials/materials.controller.ts`
* Service logic: `backend/src/materials/materials.service.ts`

--- THE `create()` METHOD PIPELINE ---
When a POST request hits `/materials`:
1. The service looks up the very last Material added, ordering by `createdAt` desc.
2. It extracts the integer from the `materialId` (e.g., matching `12` from `M0012`).
3. It increments the number and formats it back to a 4-digit padded string (e.g., `M0013`).
4. It sets a default `branchId` (e.g., `B00001`), preparing the schema for future 
   multi-branch inventory support.
5. The record is persisted to the Prisma database.
